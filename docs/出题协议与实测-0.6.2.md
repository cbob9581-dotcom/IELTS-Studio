# 0.6.2 出题协议与实测

## 规则由程序和服务共同执行

| 环节 | 明确约定 |
| --- | --- |
| 出题 | 科目与部分、题型蓝图、每个题目对象覆盖的编号及分值、字段骨架一起发送。客观题骨架使用 evidenceSourceIds，程序从真实段落或发言提取证据；判断题必须包含具体陈述。 |
| 听力脚本 | 模型保留完整发言和固定来源 ID；正文与证据保持原样。长发言在语音渲染时按句或词边界分成不超过 500 字符的片段，不能因语音片段限制拒绝整段独白。 |
| 校审 | 使用组卷后的题号。共用缺陷涉及多题时，用 affectedQuestionIds 明确列出同一部分的所有题号，不能只在原因中笼统写“第 6–10 题”。 |
| 定点修复 | 程序先映射回原稿题号，传入明确的 requiredQuestionIds。只允许改指定题目的可编辑字段，不能更改原文、编号、分值和题型。未知题号、越界字段或缺失修复会被拒绝。 |
| 失败反馈 | 独立解题、文字校审、缺陷复核及修复响应有结构问题时，向同一服务反馈具体错误及原范围，最多再修复一次，沿用持久请求记录和请求预算。缺少的题号、超范围题号和所需数量必须明示。 |
| 整卷检查 | 完整三篇 Academic 阅读合计须为 2150–2750 词；不把该范围用到单篇训练。若需要调整一篇，反馈其它两篇总量和本篇所需范围，服务同时修正文章、题目及证据。 |
| 缓存及音频 | 旧的 AI 通过记录仍须满足当前整卷规则。未通过的文字不能发布或授权 TTS；通过后由用户明确选择音频来源。 |

完整 Academic 阅读总字数依据：[IELTS 官方格式说明](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-reading)。单篇创作目标与官方完整卷总量是两种不同要求。

## 真实生成测试方法

2026-10-22 从正式桌面应用的考试模式点击“AI 生成整套”，主题留空，由配置的 DeepSeek 服务选题和出题。测试不手写题目、不替换模型响应、不人工补答案、不修改校审结论。原始响应和服务修复响应保存在本地任务目录，不进入 GitHub。

第一次在听力 Part 2 暴露原有 500 字符验收误用；原始独白未改写，修正语音边界后继续同一任务。四科 12 个部分生成后，独立校审发现了无来源答案、错配选项及缺失判断陈述。自动修复又暴露了成组题号与原稿题号约定不一致。初次阅读三篇共 1863 词，不能按完整模拟卷放行。这些失败都保留在原任务中，不作为成功证据。

语音合成在本次测试中保持关闭。文字完成不代表已有可播放的听力录音，也不代表评分已达到人工考官校准水平。

## 本次最终结果：失败，未发布

本次整套任务在原定 40 次文字请求用尽后停止，没有提高预算继续试。用量记录为输入 387722、输出 47770 Token；实际费用以供应商账单为准。TTS 请求为 0，没有生成音频文件。

12 个部分已生成，当前草稿包含听力 40 分、阅读三篇共 2243 词及 40 分、两项写作和口语提示，但**未完成最终独立校审，不是可用整套试卷**。听力采用 39 个题目对象覆盖 40 个答案位置，其中一个多选题对象覆盖两个编号。

后续修复确实发现了新的问题：匹配题答案对象使用了另一个题干的键；阅读证据引用指向标题而非正文。系统完成两轮文字修复后，最终复核被预算阻止。不能据此推断这些问题已全部解决，也不能把程序测试通过当作真实出题通过。

本版已实现连续共用说明的匹配题整组修复，以及仅在试卷哈希、来源指纹和校审协议一致时复用失败校审，避免修复前重复校审。本地 Rust 检查为 162 项通过、7 项跳过，正式桌面构建通过；这些检查不保证模型内容正确。剩余重点是匹配答案键的确定性检查、证据实际定位和修复后的局部验收，不能继续依赖整卷模型反复互审消耗预算。
