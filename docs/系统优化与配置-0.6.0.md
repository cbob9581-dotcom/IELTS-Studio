# IELTS Studio 0.6.0：配置与恢复

## 安装与本地资料

安装 `dist/0.6.0/IELTS Studio_0.6.0_x64-setup.exe`。沿用设置中的现有资产库和学习目录，不要为升级另建空资料库。普通设置保存在本机应用配置目录，API 密钥保存在 Windows 凭证管理器，均不包含在安装包和 Git 仓库中。

任务中心由桌面后台管理，页面关闭或切换后继续工作。程序退出后，下次启动将未完成任务标为暂停，用户选择继续后恢复；完成的批次、题目、原始响应和音频保留。考试期间后台任务在步骤边界等待，实时语音优先。暂停也在当前步骤结束后生效，不能撤回已发出的云请求。

## 云服务配置

以下为本机已有配置，可在“设置”中逐项填写并保存。地址、模型权限、地域必须与自己的服务账号一致；保存设置不会自动合成听力。

| 服务 | 基础地址 | 当前模型 | 超时 / 输出上限 |
| --- | --- | --- | --- |
| 出题、资料整理 | `https://api.deepseek.com` | `deepseek-flash` | 300 秒 / 16384 tokens |
| 语音识别 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3-asr-flash` | 120 秒 / 4096 tokens |
| TTS | `https://dashscope.aliyuncs.com/api/v1` | `qwen3-tts-flash` | 120 秒 / 4096 tokens |
| 口语音频评测 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3.8-omni-flash` | 300 秒 / 4096 tokens |
| MinerU | `https://mineru.net/api/v4` | `vlm` | 120 秒 |

听力 TTS 音色填 `Serena|Elias|Neil`，分别对应说话人 A、B、旁白；配置中需有三种不同音色。语言为英语。口语评测须使用支持多段音频输入的模型；识别文本不能代替发音评测。

后台设置默认：任务并发 2、OCR 并发 2、TTS 并发 2、每任务文字/评测请求预算 40、内容修复最多 2 轮。预算记录在资产库 SQLite 中，未知结果的请求也占用一次预算；重试同一失败任务不会清零。请求数和服务返回的 token 用量是实际记录，无法据此保证固定价格或剩余分钟数。达到预算先查看失败步骤与保存结果，再按需调整预算并继续，避免重复新建任务。

## 真题整书、图片、答案与解析

整书从“真题资料库”导入，分批解析后按 Test、科目、部分定位。不要把一整本书当作一套卷直接生成。答案、解析可作为独立文档加入同一资料项目，分别绑定 Test、科目和题号；解析不能自动充当答案键。界面显示各套卷缺题、缺答案、冲突与待确认项。

PDF 的页面、原图和来源位置与题目一起保存。文本来源按实际行 ID 绑定；图片中的答案转写需要核对原图后确认。多选组合按占用题号范围匹配答案，例如 23–24 是一个两分题组，不要求复制为两个相同题目。已解析批次和已整理部分可复用，某批失败不丢弃其他成功结果。

发布前核对本套所选部分及答案。缺答案、图片不可答或来源冲突时保留为资料草稿，明确展示具体缺项；不会用猜测答案凑成正式卷。修复对应项后继续原项目，无需再次上传整书。

## 原创出题与听力费用保护

先生成题目文字，程序整理结构、题号与格式，然后独立解题并核对答案。有确定内容错误时只修复对应题目，冻结正确原文与无关题目；确需改文章、脚本或图表时必须明确标识。缺陷复核区分不可答、错答案与可选措辞建议。NOT GIVEN 允许原文没有相应比较信息，不能以此误判缺材料。

文字校审与用户核对完成后，再单独选择听力来源：

1. 从真题 Audioscripts 提取脚本并核对，再选择 TTS。
2. 用户直接提供脚本，整理角色、分段与停顿，再选择 TTS。
3. 上传一个或多个 MP3/WAV 等音频，绑定各 Part 和播放顺序，不经过 TTS。

已完成音频按片段保存；相同内容和服务参数可复用。合成请求发出前写入记录，返回后先保存原始音频，再处理媒体信息。已知下载地址的失败只重试下载。结果未知时停止自动重发，普通“继续”不会再次合成；只有明确点击“重新请求结果未知的听力片段（可能再次计费）”才解除该保护。已完成片段不重做。换音色、模型或文字属于不同合成内容。

## 评测与流畅性

口语使用本次会话原始录音整体评测，四项指标等权，证据绑定录音与时间段，可点击回听。结果属于 AI 参考分，尚未经人工考官标注语料校准；校准界面支持导入 JSON/JSONL 后计算误差和重复测量波动，不会因此调用模型。

场景采用已解析模型缓存，每次进入克隆骨骼与材质，并释放实例几何、骨骼纹理和渲染上下文，修复反复进房间的缓冲区累积。口型根据音频时间与频谱驱动，属于近似动画。实际 RTX 5060 Laptop、1440×1000、Edge 无头测试中：20 次进入只读取一次 GLB，连续运行 30 分钟无记录错误；稳定阶段 P95 帧间隔约 4.3 毫秒。这不代表冷启动没有短暂卡顿，也不等于云端语音往返延迟。

本轮实际发布验收：剑雅 17 Test 1 阅读（40 个计分位置，复用已有解析和整理结果，无新增提取请求）；原创阅读（三篇、40 分，经独立校审后发布）。同一原创卷两次重审的输入用量由约 88971 tokens 降为 16569 tokens；这是单样本实测，不是所有题型的固定压缩率。原文完整保留，重复证据改为原段落引用，独立解题输入不含答案或这些证据引用。

本轮没有发送 TTS 请求。不能把单套资料验收当作所有剑雅、图片 OCR 或所有生成题型都已达到固定成功率。

最终本地验证：147 项 Rust 核心测试、86 项前端测试、10 项 Edge 端到端测试通过；7 项依赖额外本地资料的 Rust 测试和 1 项前端测试跳过。
